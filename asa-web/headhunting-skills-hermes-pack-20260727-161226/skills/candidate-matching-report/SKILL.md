# 候选人-岗位匹配分析报告

根据候选人简历（.docx）和岗位 JD，生成结构化的匹配分析报告，输出为排版完善的 .docx 文件到桌面。

## 触发条件

- 用户要求对某个候选人做岗位匹配分析
- 用户提供了简历文件 + 岗位要求
- 用户说"匹配下""分析下人岗匹配度"等

## 输入要求

1. **候选人简历**：.docx 格式，用 `python-docx` 提取文本
2. **岗位 JD**：文本形式，**必须包含岗位职责、学历要求、经验要求、加分项**，总长度不低于 200 字；不足时主动向用户索要（cron 模式下见"无人值守模式"）

## 报告结构（8 部分）

### 一、硬性门槛对照（表格）

表格列：要求 | 候选人情况 | 判定（✅/⚠️/❌）

必填行：
- 学历与专业
- 工作年限
- 行业背景
- **目前所在公司主营业务**：明确写出候选人当前公司的具体业务方向（如"新能源汽车零部件 OEM"、"B2B SaaS 企业软件"），与目标岗位所在行业的匹配度判定：✅ 高度吻合 / ⚠️ 部分关联 / ❌ 跨行业
- **薪资区间对照**：从简历或常识估算候选人当前薪资包，与目标岗位 offer 范围做对比，标注是否存在薪资差距风险（⚠️ 期望高于预算 / ✅ 在范围内 / ❌ 差距超 30%）
- **跳槽频率**：计算各段在职时长，标注平均在职时长（月），低于 18 个月标为 ⚠️，低于 12 个月标为 ❌

### 二、岗位职责逐条匹配

- **目标公司背景说明（首段）**：先用 2-3 句话说明目标公司的主营业务、规模阶段、行业定位，作为整体匹配判断的背景上下文
- 每条 JD 职责用 ★ 评级（1-5 星）
- 引用简历中具体经历佐证
- 如候选人来自竞品公司或同赛道公司，在对应职责行加注「🏆 竞品背景」标记，供客户参考

### 三、加分项核查（表格）

- 逐项核对 JD 加分项
- 表格列：加分项 | 候选人情况 | 判定（✅/⚠️）

### 四、潜在风险与关注点

每条风险必须包含：
- **风险等级**：🔴 高（可能直接影响推荐决策）/ 🟡 中（需电话探测后判断）/ 🟢 低（可接受）
- **风险描述**：具体说明，避免空泛
- **验证建议**：告知猎头应在电话或面试中用哪个问题来核实此风险

必须覆盖以下维度（有则写，无则明确标"无此风险"）：
- 角色转型风险（跨行业 / 跨职能）
- 跳槽频率 / 稳定性（结合 Section 1 的跳槽频率数据）
- 薪资期望差距（结合 Section 1 的薪资对照）
- 能力缺口
- 竞业禁止 / 保密协议风险（前公司是否竞品）
- 候选人动机与意愿

### 五、综合匹配度评分

**评分维度根据岗位类型动态选择**（从下方维度池中选取最相关的 4-5 个，不相关的不写）：

| 维度 | 适用岗位类型 |
|------|------------|
| 教育背景 | 所有岗位 |
| 技术深度 | 研发/技术/数据岗 |
| 行业经验 | 所有岗位 |
| 管理能力 | 管理/团队 Leader 岗 |
| 产品思维 | 产品/增长/运营岗 |
| 业务拓展能力 | 销售/BD/商务岗 |
| 客户服务敏感度 | 客成/售后/服务岗 |
| **主营业务匹配** | 所有岗位（必选） |

**主营业务匹配**评分标准（满分 100）：
- 80-100：完全一致（同行业同赛道）
- 60-79：高度相关（上下游或相邻行业）
- 40-59：部分交叉（有可迁移经验但需适应期）
- 0-39：跨行业（需重点风险提示，在 Section 4 标 🔴 高风险）

综合百分比 = 各维度加权平均，大字居中显示。评分条格式：`'█' * n + '░' * (20-n)`（每格 5%）

### 六、面试考察建议（表格）

- 每个考察维度 + 建议问题（含具体话术）
- 表格列：重点考察维度 | 建议问题方向

### 七、初次电话沟通指南

- **7.1 通话目的**：建立联系、确认基本情况、筛选关键风险
- **7.2 四阶段话术**：
  - 阶段一：开场破冰（2-3分钟）
  - 阶段二：现状摸底（5-7分钟，包含薪资现状、稳定性意愿）
  - 阶段三：岗位匹配探测（8-10分钟，4个方向各配具体问题）
  - 阶段四：信息交换与收尾（5分钟）
- **7.3 电话后评估清单**：6 维度通过标准 vs 红灯信号表格
- **7.4 禁忌提醒**：4 条红线

### 八、结论

- 一句话推荐判断（强推/可推/观望/不推）
- 关键风险提示（引用 Section 4 中 🔴 高风险条目）

## 生成流程

```
1. 用 python3 提取简历文本（优先 python-docx，失败则尝试 markitdown）
2. 若 JD 不全（<200字），交互模式下向用户索要完整 JD；
   自动处理时在报告封面注明"JD 不完整，准确性受限"，各行标 ⚠️
3. 分析岗位类型，动态确定 Section 5 评分维度组合
4. 按 8 部分结构完成匹配分析，输出结构化 JSON
5. 调用 scripts/report_template.py 生成 .docx：
   python3 scripts/report_template.py --data '@data.json' --output "/path/to/report.docx"
6. 确认文件写入成功后结束；交互模式下 open 打开供确认
```

> **v2.0.0 架构说明（纯 Codex）**：自动报告生成不再依赖 Hermes cron 任务。
> matching_server.py 内置 Worker 线程，直接调用 Anthropic API（本地代理）生成报告。
> 队列目录从 `~/.hermes/matching_queue/` 迁移至 `~/.codex/matching_queue/`。

## 格式规范

- 字体：Calibri + 微软雅黑（中文），通过 `set_cn_font()` 设置
- 配色：
  - 大标题：`#1A5276` 16pt 加粗
  - 二级标题：`#2C3E50` 12pt 加粗
  - 三级标题：`#34495E` 10.5pt 加粗
  - 正文：`#333` 10pt
  - 辅助文字：`#787878` 9pt
  - 风险等级色：🔴 `#E74C3C` / 🟡 `#F39C12` / 🟢 `#27AE60`
- 表格：Table Grid 样式，表头深蓝底白字，数据行交替 `#EBF5FB` 浅蓝底色
- 评分条：`'█' * n + '░' * (20-n)`，每格 5%
- 报告封面副标题中显示插件版本号（v1.4.0）和生成日期

## 注意事项

- 简历 docx 提取失败时，尝试 `markitdown` 或直接用 `python3` 脚本
- **不再使用 inline heredoc 生成 Python 脚本**：改用 `scripts/report_template.py`，从根本上消除中文引号导致的 SyntaxError
- 匹配分析要有具体简历经历引用，避免空泛评价
- 评分维度必须根据岗位类型动态选择，不强行套用不相关维度
- 用户要求调整格式时，重新生成完整文件覆盖

## App 集成（v2.0.0 纯 Codex 架构）

将匹配功能嵌入猎头工作站 HTML 应用，详见：
- `references/app-integration.md` — 部署架构与前端集成要点
- `scripts/matching_server.py` — 自给自足的本地 HTTP 服务（端口 18901），内置 Worker 线程
- `scripts/report_template.py` — .docx 生成模板

**不再需要 Hermes cron 任务。**

集成步骤：
1. 启动 matching_server.py（LaunchAgent 守护，`~/Library/LaunchAgents/ai.hermes.matching-server.plist`）
   - 服务会自动恢复上次未完成的队列（存储在 `~/.codex/matching_queue/`）
2. HTML 前端添加 `.top-nav` 导航栏 + 匹配分析表单 Tab
3. 前端提交前验证 JD 长度 ≥ 200 字，否则提示用户补全
4. 前端通过 `GET /status?id=xx` 轮询报告生成进度（超时后 POST /match 返回 poll_url）
