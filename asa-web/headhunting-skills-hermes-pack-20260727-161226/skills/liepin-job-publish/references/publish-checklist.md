# 猎聘岗位发布校验清单

## 草稿自检(每次生成草稿后、填表前必做)

以下任一条不满足，先修草稿，不进入 prepare:

- [ ] client_company 是实际公司全称(微导纳米)，非分类名如半导体CIP
- [ ] city_keyword/city_choice 均非空
- [ ] private_job 为 false(用户从未要求保密)
- [ ] 多岗位 client_company 一致

## 发布前

- 确认用户明确要求发布/上架岗位；真实发布必须有明确授权。
- 确认 Chrome CDP 端口可用，默认 `9223`。
- 确认猎聘已登录；若页面跳登录页，暂停并让用户手动登录。
- 确认职位草稿 JSON 至少包含：代招企业、职位名称、职位类别、城市、薪资、年限、学历、行业、JD、招聘人数、截止日期。
- 先跑 `prepare`，不直接发布。

## 页面字段读回

- 代招企业：输入框值或展示区必须能确认目标公司；平台可能对外展示为匿名公司。
- 职位名称：必须读回目标职位名。
- 职位类别：必须读回目标职位类别。
- 工作城市：必须读回城市标签，例如 `广东·深圳`；不要只相信点击动作成功。
- 薪资：低薪、高薪、月数均读回。
- 工作年限、学历、行业、职位描述均读回。
- 职位保密开关按草稿要求设置。
- 协议勾选。
- 发布按钮可用。

## 发布后

- 等待结果页，不只看按钮点击成功。
- 若页面提示“职位已提交/审核/已发布”，记录提示。
- 进入职位列表 `https://h.liepin.com/job/showlistpage?jobStatus=11` 验证职位名、企业、状态、更新时间。
- 如果发布页仍显示校验错误，如“请填写工作城市”，不要宣称成功；回到字段补选后重试。

## 已知坑

- Ant Design 下拉控件只派发 DOM click 可能是假成功；优先用 CDP `Input.dispatchMouseEvent` 真实坐标点击，再读回字段。
- 城市控件有两个“深圳”节点，点击 `span.ant-tag-checkable` 比点击外层 `li#code_050090` 更可靠。
- 公司下拉候选有延迟，先输入简称/全称，等待候选项出现，再点击并读回。
- Chrome `/json/new` 需要 `PUT`，不能用普通 `GET`。
- 发布脚本新开标签页时，若旧标签页已有半填表单，注意不要误操作到空白页。
