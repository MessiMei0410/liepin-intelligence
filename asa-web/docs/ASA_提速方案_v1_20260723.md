# ASA 提速方案 v1（2026-07-23）

## 背景诊断

Kimi CLI 实际产出不慢（5 小时 25 commit，S4 全收官），感知慢来自三处：

1. **验证链无差别全量**：AGENTS.md 规定改动后必须 `npm run ci` 全绿，其中 e2e（functional + 桌面/浮窗两组截图回归）+ 真实寻访验证轮占单次开销 70% 以上，改一行文案也要全套。
2. **机器资源挤兑**：16GB 内存、常驻 100+ Chrome 进程（猎聘 CDP、X-SaaS、Playwright）、QQLive 高 CPU、双 AI 实例并行，load 常驻 3+。
3. **交接粒度太碎**：一点点修 → 每次都要重建上下文 + 全量验证，固定成本摊不薄。

## 方案：三层验证门禁（核心）

### L1 快速门禁 —— 每个 commit / 小任务必跑（约 1-2 分钟）

```
npm run ci:fast   # 新增脚本 = typecheck && lint && test && build && check:api-drift
```

- 纯文案、样式、prompt、docs 改动：只跑 L1。
- 覆盖 90% 的日常改动。

### L2 模块门禁 —— 按需触发

| 改动范围 | 追加跑 |
|---|---|
| Core API / 数据结构 | `npm run test:contract` |
| 前端交互流程 | `npx playwright test --project=functional`（不跑截图） |
| 寻访策略/池逻辑 | 单岗位真实寻访验证一次 |

### L3 全量门禁 —— 里程碑或每日一次

```
npm run ci   # 完整链，含两组截图回归
```

- 触发时机：每个里程碑收官（如 S4-5 这种）、每天收工前一次。
- 真实寻访验证轮：从"每任务一次"降为"每里程碑一次"。

### 落地改动

1. `package.json` 新增：
   - `"ci:fast": "npm run typecheck && npm run lint && npm run test && npm run build && npm run check:api-drift"`
   - `"ci:e2e-functional": "playwright test --project=functional"`
2. AGENTS.md 验证段改写为三层门禁规则（上表原文写入）。
3. 截图基线只在 UI 变更的里程碑重生成，不再随任务重生成。

**预期效果**：单项任务验证耗时从 ~15-30 分钟降到 ~2-5 分钟，整体节奏快 3-5 倍；质量底线由每日 L3 兜底。

## 方案：机器资源释放

1. Playwright 限并发：`playwright.config` 设 `workers: 2`（默认按 CPU 核数起，16GB 机器扛不住）。
2. 不干活时关闭 X-SaaS / 多余 CDP Chrome 实例；QQLive 退出。
3. e2e 隔离 Core（8876）跑完确认回收（现有逻辑保留，加一条 doctor 检查项）。

## 方案：交接批处理

- 零碎修复攒成批：一张任务卡装 3-5 个同类小问题，一次交接、一次 L1+按需 L2。
- 任务卡模板固定四要素：改动文件路径 / 验收标准 / 门禁层级（L1/L2/L3）/ 是否需部署。Kimi CLI 不用自己猜。

## 方案：部署一键化

新增 `scripts/ship.sh`：build → `launchctl kickstart -k gui/501/ai.hermes.liepin-workbench` → 提示重开 ASA.app。里程碑任务最后一步自动执行，消除"改完了但 App 里看不到"的假慢。

## 不改的底线

- 正式库只读隔离、副本跑 e2e 的机制不动。
- L3 全量每日必跑一次，保证主线永远绿。
