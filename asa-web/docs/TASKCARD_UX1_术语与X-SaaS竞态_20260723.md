# 任务卡 UX-1：术语通俗化 + X-SaaS 搜人竞态（2026-07-23）

## 问题 A：UI 术语猎头看不懂（优先级高）

**改动范围**：`src/workflows/StrategyCoverage.tsx`、`src/workflows/StrategyReviewExpansion.tsx`、`src/components/RevisePlanDialog.tsx`、`src/panels/` 全量扫一遍用户可见文案；后端 `asa_floating_html` Copilot 浮窗内联文案同步扫。

**必改映射**（其余黑话按同样原则处理——用户是一线猎头，不是工程师）：

| 现状 | 改为 |
|---|---|
| 种子要素消费 | 这些信息用上了吗 |
| 已消费 / 未使用清单 | 已采用 / 没用上（附原因） |
| 扩池决策树 | 人不够时的扩圈建议 |
| 渠道效能学习 | 哪个渠道出人多 |
| 归因 / 复盘 | 没成的原因 |

原则：板块标题一律用"用户能一眼看懂的业务语言"，技术概念（strategy_v2、coverage、要素、消费、决策树、归因、校准、效能、枯竭）不得出现在 UI 文案里。

**验收标准**：`npm run test` 更新对应断言（`strategy-coverage.test.tsx` 等引用旧文案的测试同步改）；App 内五个板块标题全部业务语言化。
**门禁层级**：L1（`npm run ci:fast`）。

## 问题 B：X-SaaS 自动寻访关键词竞态（真 bug）

**现象**：自动寻访输完关键词，候选人列表还没渲染出来，流程就切换到下一个关键词，导致上一轮结果丢失/错配。此前修过一次竞态，未修干净。

**改动范围**：X-SaaS 寻访驱动层（关键词循环 + 结果等待逻辑）。

**要求**：
1. 加硬门：候选人列表出现加载完成信号（结果节点渲染或网络空闲）后才允许切下一个关键词；
2. 超时兜底（如 20s）+ 该词重试一次，仍失败记入日志并标记"跳过"而不是静默丢失；
3. 每轮关键词与结果集做轮次绑定，防止串词错配。

**验收标准**：真实寻访轮验证一次——连续 3 个关键词自动搜索，每轮结果完整呈现后才切词；日志无静默跳过。
**门禁层级**：L1 + L2（寻访策略逻辑 → 单岗位真实寻访验证一次）。
