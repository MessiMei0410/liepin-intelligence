## 0. 目标与定位

**解决的问题**：ASA 的寻访链路（S4）和直挖链路（S5）已经解决"找人"，但推荐出去的报告仍是信息罗列。资深顾问的核心功夫是**判人**：30 秒看穿一份简历——这人在团队里实际是什么角色、水平在同龄人什么分位、每次跳槽是上升还是平移、现在为什么可能动、对客户有什么风险。这一层判断目前是空白。

**一句话目标**：每个进入推荐环节的人选，都带一份"资深顾问级"评估——**轨迹、分位、动机、风险、匹配**五个维度，每条判断必须挂证据，拿不准的明说"推测"。

**定位红线**：评估器是顾问的副驾驶，不做录用/淘汰决策；它的产出永远以"建议+证据"形式呈现，最终判断权在顾问。

## 1. 业务流程

```
触发（三处入口）
 ① 人选入库后自动预评估（后台跑，不打断顾问）
 ② 推荐报告生成前强制评估（报告必须引用评估结论，不许罗列原始简历）
 ③ 顾问在人选卡上手动点"深读此人"
→ 评估器读取：简历/候选人结构化数据 + strategy_v2（岗位要求）
   + 公司图谱（雇主 tier、团队、行业位置）+ 知识库 case（客户口味）
→ 产出 assessment_v1 artifact（人×岗，同一人对不同岗评估不同）
→ 人选卡新增"评估"区 + 推荐报告引用块
→ 顾问动作回流：采纳 / 改判 / 否决（接 S4-5 评估校准，形成学习闭环）
```

## 2. 五个评估维度（资深顾问直觉的结构化）

| 维度 | 判断什么 | 证据来源 |
|---|---|---|
| **职业轨迹** | 每段经历的含金量（公司 tier/团队/汇报线）、晋升速度快慢、技术栈演进是上升/平移/吃老本 | 简历 + 公司图谱 tier + 知识库 |
| **水平分位** | 在同方向、同年限人群中的大致位置（前 10%/25%/中位） | 历史人选库做参照系 + 行业基准 |
| **跳槽质量史** | 每次移动是上升还是平移（平台/title/职责三维），当前这单对他是升是平 | 简历时间线 + 图谱 |
| **动机与时机** | 当前处境信号（公司裁员/业务收缩/融资受阻/上市节点）→ 他动的可能性和真实诉求 | 图谱公司近况 + 公开信息（只读） |
| **风险点** | gap、频繁跳动、title 通胀 vs 实际职责、过度包装信号、与岗位硬要求的差距 | 简历交叉验证 + strategy_v2 硬条件 |

**输出形态**：每个维度一句话结论 + 证据引用 + 置信度（确定/推测）。最后给一段"顾问口径摘要"——就是资深顾问在推荐报告里会写的那段话。

## 3. 数据模型

新 artifact 类型 `candidate_assessment`（schema_version `assessment_v1`），键为 `candidate_id × job_id`：

```json
{
  "schema_version": "assessment_v1",
  "candidate_id": 0, "job_id": 0, "strategy_ref": "strategy_v2 artifact id",
  "dimensions": {
    "trajectory": {"verdict": "...", "evidence": [{"type": "简历|图谱|知识库|公开信息", "ref": "..."}], "confidence": "certain|inferred"},
    "percentile": {"verdict": "...", "band": "top10|top25|median|below", "evidence": [], "confidence": "..."},
    "move_history": {"verdict": "...", "moves": [{"from": "", "to": "", "direction": "up|lateral|down"}], "confidence": "..."},
    "motivation": {"verdict": "...", "signals": [], "confidence": "..."},
    "risks": {"items": [{"risk": "...", "severity": "high|medium|low", "evidence": []}]}
  },
  "consultant_summary": "顾问口径摘要（直接可进推荐报告的那段话）",
  "advisor_action": "pending|accepted|modified|rejected",
  "advisor_note": ""
}
```

约束：**每条 verdict 至少挂一条 evidence，挂不上的必须标 `inferred`**；编造检查进契约测试（evidence 引用的简历片段必须能在该候选人数据中找到原文）。

## 4. 红线（写死）

- 评估只辅助不决策；UI 不出现"建议淘汰"类字眼，风险以"需要核实的问题"呈现。
- **敏感属性合规**：年龄、性别、婚育、地域户籍不得作为负面因子出现在任何 verdict 里（契约测试负向扫描）。
- 动机推断基于公开信息+简历，不推断个人隐私；公司近况信号必须有公开来源。
- 评估数据不出本机，不进任何对外输出；推荐报告引用前顾问可见可改。
- 遵循 UX-1：全部文案业务语言（trajectory→「职业轨迹」、percentile→「在同龄人里的位置」、inferred→「推测」）。

## 5. 分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| S6-1 | 轨迹 + 跳槽质量史（纯简历+图谱可判，不依赖外部信号） | 从三个 case 各抽 5 个历史人选回放：轨迹判断与顾问当年实际判断对照，顾问盲评"像不像资深顾问写的"；evidence 编造检查契约测试通过 |
| S6-2 | 分位 + 动机时机（引入历史库参照系 + 公司近况信号） | 分位判断在 20 个历史人选上与实际面试结果一致性 ≥ 可解释（错了的能说出为什么错）；动机信号全部带来源 |
| S6-3 | 风险点 + 推荐报告集成 + 顾问口径摘要 | 推荐报告强制引用评估块；敏感属性负向扫描通过；顾问在 App 里可采纳/改判/否决 |
| S6-4 | 校准学习闭环（接 S4-5）：顾问改判回流，评估器按客户/岗位类型调整 | 改判数据可查询；同一顾问的二次评估采纳率可度量 |

每期独立 commit；门禁按三层规则：L1 必过 + 契约测试必过 + 该期验收里的真实回放。

## 6. 度量

- 推荐报告的客户通过率（评估器上线前后对照）
- 顾问对评估的采纳率 / 改判率（改判率高 = 评估器还没学到位）
- 评估耗时：入库到出评估 < 2 分钟，不打断寻访主链路

## 7. 依赖与边界

- 依赖：公司图谱（雇主 tier）、strategy_v2、S4-5 评估校准链路；客户手册消化（等 WebBridge）完成后，S6-3 的"客户口味"维度增强，但不阻塞 S6-1/2。
- 不做：薪资定价与成单预测（那是再下一期）；人才流动雷达（S7）的"时机信号"成熟前，动机维度只用工况级公开信号。
