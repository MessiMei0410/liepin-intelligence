## 本期范围（backend-only，不做 UI）

1. **数据模型**：新 artifact 类型 `radar_scan`（schema_version `radar_v1`），字段按 PRD §3：scan_date / signals[]（company、type 六类枚举、summary、implication、**source_urls 必填**、as_of、confidence、linked_action）/ ranking[] / stats。
2. **公司池构建**：首期限 33 家客户档案公司（`knowledge_base/client_profiles_public_v1/`）+ mapping_task 已确认团队所在公司（从 agent_artifacts 聚合，去重）。
3. **信号采集器（只读）**：按公司逐一检索六类公开信号（财报/融资IPO/股权激励/组织高管变动/招聘异动/风险事件），复用现有 llm 客户端做"搜索结果→结构化信号"的抽取；每个来源失败记入 stats.sources_failed，不静默。
4. **硬约束（契约测试锚死）**：`source_urls` 为空的信号**拒绝写入**；type 必须在六类枚举内；implication 为空允许（只记事实）但 summary 必填。
5. **榜单生成**：公司 × 信号强度 × 在手岗位相关性（jobs 表在招岗位的客户匹配）排序，输出 markdown 到 `work/radar/`（不进 git）：本周榜单 = 公司、信号摘要、建议动作（发起 Mapping/激活存量/观望）、来源。
6. **接口**：`POST /api/v1/radar/scans`（手动触发一次扫描）+ `GET /api/v1/radar/scans/latest`（读最新榜单）。幂等：同日重复扫描更新同一 artifact。

## 红线

- 全部公开信息只读；不碰登录墙；脉脉类来源不做。
- 信号必须有来源 URL + 日期；implication 是推测，字段命名和文案不得暗示确定性。
- 风险类信号表述克制（写事实，不写结论性贬损）。
- 禁挖公司照常过滤（restricted 白名单出库）；费率不出现在任何输出。

## 验收标准

1. 真跑一次：≥20 家公司扫完，signals ≥ 10 条且全部带 source_urls；stats 完整；
2. 编造检查契约测试：构造无 source_urls 信号写入 → 被拒；
3. 榜单 markdown 抽查 5 条信号，来源 URL 真实可达、内容与摘要一致；
4. 与 S6-3 并行后合并，`npm run ci:fast` + `npm run test:contract` 全绿。

## 门禁层级

- L1 `npm run ci:fast` + L2 `npm run test:contract` 必过；
- 真实扫描：验收 1 必须真跑，不许只跑单测。
