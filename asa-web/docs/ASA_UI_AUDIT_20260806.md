# ASA App UI 审计与第一轮优化（2026-08-06）

## 1. 审计范围

本轮基于当前 dirty worktree 和正式 Core 数据审查，不恢复旧版，不改业务事实源。

- 桌面：1440 x 900
- ASA 浮窗：390 x 700
- 页面：Agent 首页、岗位看板、人选进度、人选列表、岗位详情、候选人详情、分析工作区
- 交互：搜索、筛选、排序、分页、详情打开、Agent 入口、键盘焦点、触控尺寸
- 约束：保持 `Agent / 岗位看板 / 人选进度 / 人选列表` 四个主入口；不引入 Motion、Magic UI 或展示型动画依赖

## 2. 总体结论

当前 ASA 已经不是“AI 默认生成的后台模板”：信息架构稳定、P0 岗位可见、状态颜色克制、详情证据链完整，也没有渐变、粒子、光束和大面积卡片装饰。主要问题来自长期增量开发后的可用性债务，而不是缺少视觉特效。

第一轮应继续采用安静、扁平、数据密集的企业工作台方向。重点是让顾问更快看清下一步行动、状态和证据，不做品牌换肤。

## 3. Findings

### P1-1 Agent 空任务首页首次进入会跳到底部（本轮已修）

**证据**：`AgentWorkspace` 对 `messages` 和 `loading` 的滚动副作用在空消息初始态也调用 `scrollIntoView`。真实桌面首屏直接落在待办列表中段，标题“今天从哪里开始？”和今日概况不可见。

**影响**：用户首次打开 ASA 看不到工作台总览，必须先向上滚动，且容易把 Agent 首页误认为只有一串待办。

**处理**：只有存在对话消息或正在生成时才滚到消息末尾；空任务工作台保持 `scrollTop = 0`。新增单测锁定该行为。

### P1-2 页面出现两套搜索入口（本轮已修）

**证据**：岗位、人选进度、人选列表已有页面内搜索；壳层顶部同时渲染“搜索姓名、公司或岗位”。移动端两条搜索框连续出现，范围语义不一致。

**影响**：重复占用首屏空间；用户无法判断上方搜索和页面搜索的过滤范围、排序与分页关系。

**处理**：移除壳层重复搜索，保留各业务页内部的结构化搜索、排序和范围筛选。

### P1-3 高频信息字号过小（本轮已修第一批）

**证据**：Agent 任务摘要、对象卡、分析表头、详情侧栏、工作流策略中大量使用 8.5-10px；在 390px 浮窗和非 Retina 缩放下明显吃力。

**影响**：顾问需要反复辨认元数据；状态、证据和辅助说明的层级差异变成“看不清”而非“次要”。

**处理**：高频元数据提升到 10.5-11.5px，正文和表格提升到 11.5-12px；保留紧凑密度，不使用随视口缩放的字号。

### P1-4 移动端触控和键盘焦点不完整（本轮已修第一批）

**证据**：移动导航、发送、详情动作、任务管理等按钮存在 25-42px 点击区域；全局没有一致的 `focus-visible` 规则；reduced-motion 仅覆盖少数动画。

**影响**：浮窗中容易误触；键盘用户难以判断当前焦点；系统减少动态效果设置不能完整生效。

**处理**：移动端可见命令按钮按 44px 最小目标修正；补齐统一 2px 焦点环；reduced-motion 覆盖动画、过渡和滚动行为。

### P1-5 分析侧栏暴露技术字段（本轮已修）

**证据**：分析范围直接显示 `days`，数据口径直接显示 ISO 时间和裸版本号。

**影响**：业务用户需要自行翻译字段；界面与分析主体的中文口径不一致。

**处理**：改为“统计周期 / 近 7 天”“数据截至 YYYY/MM/DD HH:mm”“口径版本 …”，并覆盖岗位、候选人、渠道及日期范围字段。

### P1-6 慢工作台请求会阻塞固定分析刷新（本轮已修）

**证据**：固定分析创建接口和模板列表读取均成功时，只要并行的工作台请求未结束，前端仍等待统一 `Promise.allSettled` 结果后才更新模板状态。隔离 Core 下可复现“创建成功但列表 10 秒内不出现”。

**影响**：用户会重复创建固定分析，或误以为保存失败；工作台大数据读取把无关模块拖成加载态。

**处理**：工作台与固定分析请求继续并发，但各自响应后立即更新各自状态；一个模块变慢不再阻塞另一个模块显示。刷新轮次带序号，旧轮次晚到的空列表不会覆盖新建结果。

### P2-1 右侧上下文栏信息密度偏低（本轮已修）

**证据**：非 Agent 页面固定占用 320px，但通常只展示今日节奏、固定分析和连接状态。

**影响**：1440px 桌面下压缩主表格和分析区，右侧仍留下大量空白。

**处理**：宽桌面收敛到 288px；1180px 以下沿用 280px，1050px 以下隐藏或在移动端移至内容后方。

### P2-2 动效规则分散（本轮已修基础设施）

**证据**：存在多组 `.2s ease`、`.35s ease`、循环 pulse 和局部 reduced-motion。

**影响**：状态变化的节奏不一致，后续新增动画容易继续漂移。

**处理**：加入统一 easing token 和全局 reduced-motion 兜底。本轮未新增列表 stagger、数字滚动、图表绘线、背景特效或磁吸按钮。

## 4. 已确认的优点

- P0 岗位在列表和岗位详情中都有可见标识。
- 停止推进状态与正常推进使用不同色调，候选人详情保留人工确认动作。
- 岗位详情同时呈现漏斗、岗位 Brief、候选人、待办和来源信息，证据结构完整。
- 候选人详情保留身份、职业事实、履历、记录、评估、人岗关系和最近动态。
- 表格在窄屏使用局部横向滚动，未出现页面级横向溢出。
- Agent 是明确的主交互面，旧总览能力已并入空任务首页，四入口迁移有文档与测试依据。

## 5. 后续优先项

### P1 大待办分批展开

当前待判断真实总数超过 400，接口返回窗口仍可能有 200 多项。“查看全部”会一次渲染整个已加载窗口。下一轮应改为每次追加 20-30 项，并持续显示“已展示 / 已加载 / 真实总数”。

### P1 对话框焦点闭环

部分 React 对话框支持 Escape 和 autoFocus，但焦点约束、关闭后归还触发按钮尚未统一。应抽出本地 dialog focus helper，覆盖候选人确认、任务批量归档、分析模板和工作流产物。

### P2 移动表格扫描

岗位和人选表格已局部滚动，但人选表右侧字段需要横向滑动。可评估固定首列，或在 390px 下改成两行关系列表，同时保留桌面表格。

### P2 信息口径继续中文化

分析表格已映射常用字段，未知列仍回落到原始字段名；岗位状态仍存在少量 `active`。应在 Core/共享映射层统一，不在页面继续堆本地字典。

## 6. 验证标准

- Agent 空任务首页首次进入 `scrollTop = 0`。
- 桌面和 390 x 700 均无页面级横向溢出。
- 三个业务列表各只有一个搜索框。
- 浮窗可见命令按钮最小触控目标为 44 x 44px。
- 键盘 Tab 可见统一焦点环。
- `prefers-reduced-motion: reduce` 下无持续循环动画或平滑滚动。
- L1 `npm run ci:fast` 通过；UI 里程碑截图在桌面和浮窗两组更新并复跑。
