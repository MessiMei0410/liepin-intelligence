## 本期范围

1. **改判样例库**：advisor_action ∈ {modified, rejected} 的 assessment 自动进入校准集，结构为 {维度, 机器原判, 顾问改判(advisor_note), 客户, 岗位类型, as_of}。只存改判内容和维度标签，不存简历原文。
2. **校准注入**：生成新评估时，检索校准集中**同客户或同岗位类型**的最近 N 条（建议 3-5 条）改判样例，作为 few-shot 上下文注入评估 prompt——让机器知道"这位顾问在这类岗位上不看学历/接受平移/看重稳定性"等个人口径。无样例时不注入，不编造。
3. **采纳率度量**：`GET /api/v1/assessments/calibration/metrics`——按维度（轨迹/分位/动机/风险）×客户聚合：采纳率、改判率、否决率；数据不足的分组如实返回 null。
4. **校准报告（周度手动触发即可，不做定时）**：`POST /api/v1/assessments/calibration/report` 生成 markdown：本周改判集中在哪些维度、哪些客户口径最特殊、建议关注的系统性偏差。输出到 `work/calibration/` 不进 git。

## 红线

- 改判样例只影响判断**口径**，不放宽证据强约束（verdict 仍必须挂证据、标置信度）；
- 校准注入内容不得出现在 UI/推荐报告对外文本里（"顾问上次改判过"这种话永不外泄）；
- 敏感属性红线不变：改判样例若含敏感因子，拒绝入库（契约测试）；
- 文案业务语言：calibration → 「评估校准」，采纳率 → 「顾问点头率」。

## 验收标准

1. 端到端：对某 assessment 做一次 modified（写改判意见）→ 校准集出现该样例 → 同客户同人重新生成评估 → 新结论体现改判倾向（人工核验，记录对比）；
2. 度量接口数据与库内 advisor_action 实际分布一致；
3. 契约测试：含敏感因子的改判样例入库被拒；注入样例数上限生效；无样例时 prompt 不含校准段；
4. 采纳率看板数据在 Diagnostics 或评估区可见（简单表格即可，不做图表）。
