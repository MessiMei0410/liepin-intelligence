## 本期范围（三件事）

1. **榜单 → 一键发起 Mapping**：`POST /api/v1/radar/scans/latest/actions/start-mapping`（body: company + job_id + Idempotency-Key），行为：
   - 调 mapping_task 既有创建链路，`trigger="radar"`；
   - 目标团队建议带上该公司的雷达信号上下文（把 signals 里该公司的 summary+implication 注入团队定位的 prompt 上下文，**不进最终 artifact 的对外字段**，只提升定位质量）；
   - strategy_ref 取该 job 最新 strategy_v2（无则允许 null 并在 artifact.stats 注明）。
2. **激活存量人选**：`GET /api/v1/radar/scans/latest/actions/activate?company=`——从人才库筛该公司现职/曾任职的候选人（现职优先），返回候选清单（id、遮罩名、当前职务、入库阶段、最近一次动作日期），只读不写库，动作由顾问执行。
3. **信号注入 S6 动机维度**：生成 assessment 时，若候选人现职公司在最新 radar_scan 里有未过期信号，把信号（summary + as_of + source_urls）作为 evidence 追加进 motivation 维度（type="雷达信号"），confidence 按信号置信度封顶 inferred；无信号则行为不变。
   - 实现位置：`candidate_assessment.py` 读取侧追加一个雷达信号查询函数调用（注入 evidence），**不重写既有生成逻辑**；`llm.py` 尽量不动，若必须动，仅限追加函数。

## 验收标准

1. 端到端真跑：对最新榜单里一家公司发起 Mapping → mapping_task 创建成功、trigger=radar、目标团队≥1、stats 有 radar 上下文标记；同日重复发起幂等（不重复建 task 或明确返回已存在）。
2. 激活清单：选一家库里有人的公司（如矽力杰/MPS），返回清单字段齐全。
3. 动机注入：找一个现职公司有雷达信号的候选人生成 assessment → motivation 维度 evidence 出现"雷达信号"条目且带来源；无信号公司候选人评估结果与之前一致（回归）。
4. 契约测试：trigger=radar 合法性、幂等、注入 evidence 结构校验、无信号不注入。
5. 协同检查：提交 diff 不含任何 S8 文件（git show --stat 自证）。
