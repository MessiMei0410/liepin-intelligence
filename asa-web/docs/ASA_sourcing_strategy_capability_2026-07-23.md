# ASA 寻访策略能力建设方案（通用化）

日期：2026-07-23
撰写：Kimi
定位：战略 PRD 第 3 章的展开与通用化。士兰微 TME 是第一个校准样本（种子数据见 `knowledge_base/seed_silan_tme_v1.json`），本方案回答的是：**如何让策略 Agent 对任何岗位都能产出资深顾问级的寻访策略。**

---

## 0. 从一个案例里抽象出的方法论

士兰微案例的价值不在那几家公司名单，而在顾问（和客户）制定策略时实际使用的**思维结构**。从那份需求梳理表可以反推出资深顾问的策略生成过程：

### 0.1 策略的四个锚点

一份高质量策略不是从 JD 文本里抠关键词，而是先锚定四个维度：

| 锚点 | 士兰微案例 | 通用问法 |
| --- | --- | --- |
| **客户的客户** | 联想/联宝/荣耀、浪潮/新华三、车企 | 这个岗位服务谁？谁的需求在驱动它？ |
| **产品/技术线** | 多相控制器、DrMOS、POL、eFuse | 做什么技术？技术词比方向词（"PC电源"）更忠实 |
| **竞争格局** | MPS、矽力杰、杰华特、晶丰明源 | 客户在和谁抢生意？友商的人最对口 |
| **场景/赛道** | PC / 服务器板级电源 / ADAS | 同一岗位在不同场景可能是不同的人 |

JD 往往只写其中一两个锚点，**其余要靠顾问的行业知识补齐——这正是知识库要替 Agent 补的课**。士兰微案例里"PC电源"→"多相/DrMOS/POL"的偏差，本质就是只锚了场景、丢了产品线。

### 0.2 目标池的推导逻辑（可泛化）

顾问的目标公司池不是拍脑袋名单，是三条迁移路径的并集：

1. **同层迁移**：友商同职能（器件原厂 TME → 器件原厂 TME）。对口度最高，池子最小。
2. **逆向迁移**：客户的客户里的工程师（整机厂电源工程师 → 器件原厂技术市场）。懂应用端，是客户明确认可的来源（客户把客户名写进了检索词）。
3. **相邻迁移**：相邻产品线/相邻职能（其他电源管理原厂、方案商、FAE→TME）。兜底池，需要顾问逐案确认。

**不同岗位类型，三条路径的优先级不同**：技术市场岗优先同层+逆向；纯研发岗可能逆向不通（整机厂电源工程师未必能做器件设计）；销售岗可能客户侧迁移最顺。→ 这是"岗位原型"要沉淀的核心参数。

### 0.3 关键词体系 = 锚点的结构化组合

有效关键词组 = **公司词 × 职能词 × 产品技术词** 的绑定组合，每组绑定一个画像假设（"这组词打的是哪类人"），而不是一盘散词。士兰微案例的三组（competitor_tme / customer_power / product_tech）就是这个结构的实例。

### 0.4 策略必须自带"预期与放宽预案"

资深顾问下单前心里有数："T1 池大概多少人，找不到就往哪退"。把预期召回量级和放宽预案写进策略对象，复盘才有基准——这是从"关键词匹配"到"策略管理"的质变。

## 1. 能力架构：策略 Agent 的通用工作方式

### 1.1 输入规范（策略生成的原料）

按信息质量分三级，Agent 必须显式声明当前处于哪一级：

1. **L1 一手需求资料**（如士兰微这份梳理表）：锚点齐全，直接结构化。
2. **L2 结构化 JD + 顾问口述补充**：Agent 先从 JD 抽锚点，缺哪个锚点**主动向顾问提问**（"这个岗位的友商名单您有吗？"），而不是瞎编。
3. **L3 只有 JD**：Agent 用知识库推断补齐锚点，但每个推断标记"待确认"，顾问校准后才执行。

> 当前 ASA 的策略生成等于永远按 L3 裸跑——这是"泛泛关键词匹配"的结构性根因。**主动向顾问要缺失锚点**是成本最低的能力提升。

### 1.2 五步判断树（战略 PRD 已定，此处补通用化细则）

岗位本质定位 → 目标公司分层池（三条迁移路径）→ 职能职级映射 → 关键词组绑定画像 → 预期与放宽预案。每步结构化留痕，顾问可逐条推翻。新增：

- 第 2 步公司池必须标注**迁移路径**（同层/逆向/相邻）和**来源**（客户资料/知识库/模型推断），推断的公司进"待确认"区。
- 第 4 步每组关键词必须绑定画像假设；禁止不与公司池或技术词锚定的孤立方向词。

### 1.3 输出即原型

每份策略定稿后按种子 schema（`seed_silan_tme_v1.json` 的结构）存为**岗位原型**：锚点、迁移路径优先级、有效关键词、排除规则、复盘结论。下一个同类岗位从最近的原型出发迭代，而不是从零生成。

### 1.4 复盘闭环（已在战略 PRD，重申通用口径）

每轮结束用漏斗数据 + 评估结果回答一个问题：**策略错了还是执行错了？** 判定逻辑：
- 召回量远低于预期 → 关键词/公司池问题（策略）
- 召回正常但 detail 抓取失败多 → 执行/渠道问题
- 入库正常但高分率低 → 画像偏差（策略）或评分标准偏差（评估）
- 某渠道 0 且归因为 session/page → 渠道问题，不据此改策略

## 2. 校准与评测：让"像顾问"可度量

### 2.1 Case 库建设

一个 case 不够。策略能力的校准基准是**多个真实 case 的集合**。每个 case 按同一种子 schema 结构化：岗位 + 锚点 + 顾问定的目标池/关键词 + 实际结果（成单路径）。建议优先收集：

- 2-3 个**不同岗位类型**（如：研发岗、销售岗、另一赛道市场岗）——迁移路径优先级因类型而异，单类型 case 会教出偏科 Agent；
- 至少 1 个**当年难找的岗位**（多轮才关的）——失败/挣扎 case 对复盘器的训练价值最高。

### 2.2 回放评测

每次修改策略生成逻辑（prompt、判断树、知识库接入），用 case 库回放：

- **目标池重合度**：Agent 生成的 T1/T2 公司池 vs 顾问当年实际定的池（recall/precision）
- **关键词有效率**：Agent 关键词组命中当年有效来源人选的比例
- **锚点完整率**：四锚点被正确锚定的比例（士兰微类偏差会被这项直接抓住）

指标进 CI 思维：策略逻辑改动不许让回放指标倒退。

### 2.3 横向规律萃取

每积累约 10 个 case，做一次横向萃取（顾问 + Agent 一起）：哪些判断规则反复出现（如"器件原厂市场岗 → 逆向迁移必开"），固化进判断树的默认参数——**这是把顾问直觉变成系统资产的正式通道**，也是知识库 Agent 的核心产出。
