## 3. 工程规范（这套机制比单个功能更重要）

### 3.1 三层验证门禁（提速方案 v1，e6b0427）

- **L1 快速门禁**（每个 commit/小任务）：`npm run ci:fast` = typecheck+lint+test+build+api-drift，约 2 分钟；
- **L2 按需门禁**：动 Core API/数据结构 → `npm run test:contract`；动前端流程 → `npm run ci:e2e-functional`；动寻访逻辑 → 单岗位真实验证；
- **L3 全量门禁**（里程碑+每日一次）：`npm run ci`（含截图回归）。
- Playwright workers 限 2（16GB 内存约束）；部署一键化 `bash scripts/ship.sh`（build+重启 Core+提示重开 App）。

### 3.2 任务卡制度（asa-web/docs/TASKCARD_*.md）

模板四要素：改动范围/验收标准/门禁层级/是否需部署。红线写死、验收必须真实环境跑、零碎修复攒批处理。已发卡：UX-1、S5-1、S5-2（升级版含破冰素材）、S6-1、S6-4、S7-1、S7-2、S7-3。

### 3.3 验收机制（特色）

- **真实环境验证**：接口真调、X-SaaS 真搜（3 关键词连续搜验证竞态）、Mapping 真生成；
- **顾问盲评**：S6-1 用三个 case 各 5 个历史人选回放，顾问盲评"像不像资深顾问写的"，三份全过才解锁 S6-2（验收记录 8adecdc）；
- **证据强约束**：评估/雷达/名单的每条结论必须挂可查证据（简历原文逐字校验、来源 URL 必填），无证据标"推测"——契约测试锚死，防 LLM 编造。

## 4. 各线要点（Codex 接手所需的最小上下文）

### S5 Mapping 直挖
- artifact `mapping_task`（mapping_v1），复用 agent_artifacts；`source_urls` 必填（无来源人名拒绝写入）；
- 入口：`POST /api/v1/jobs/{id}/mapping-tasks`；状态机七态 PATCH；破冰素材 icebreaker 在确认时生成，契约测试拦模板话术；
- S5-3 回流：只回流"确认过"的团队，候选人名永不进图谱，禁挖二次校验，原图谱逐字节保留（幂等）；
- 指标：`GET /api/v1/mapping-tasks/metrics`（线索有效率/转化率/覆盖率/高分率对照）。

### S6 判人评估器
- artifact `candidate_assessment`（assessment_v1），键 = 人×岗；五维：职业轨迹/水平分位/跳槽质量史/动机时机/风险点；
- 敏感属性（年龄/性别/婚育/户籍）契约测试负向扫描；只辅助不决策；
- S6-4 校准闭环：advisor_action（accepted/modified/rejected）写回 → 改判样例库 → 同客户/同岗类型 few-shot 注入 → "顾问点头率"度量（`GET /api/v1/assessments/calibration/metrics`）。

### S7 人才流动雷达
- artifact `radar_scan`（radar_v1）+ `radar_weekly`；六类信号（财报/融资IPO/股权激励/组织高管/招聘异动/风险），全部公开只读、来源 URL 必填；
- 信号 60 天过期降权（×0.2），全过期掉榜；同日幂等；
- 联动：榜单一键发起 Mapping（trigger=radar）、激活存量人选清单、信号注入 S6 动机维度；
- **定时任务（Blueprint Automation）**：每周一 07:43 Asia/Shanghai，cron `43 7 * * 1`，入口 `scripts/radar_weekly_scan.py`，周报推送 Copilot 浮窗。

### UX-1
- ~40 处技术黑话→业务语言（映射表在 TASKCARD_UX1）；原则：**技术词不上 UI**；
- X-SaaS 竞态根治：三重硬门（本轮关键词生效+计数就绪+加载消失）才切词，超时重试不静默丢词，轮次绑定防串词（`scripts/xsaas_candidate_search.py`）。

### S8 岗位画像
- `GET /api/v1/jobs/{id}/profile-insights`：真实候选人职责事实聚类，min_source_count=3 防瞎编，feedback 路由已备。

## 5. 全局红线（任何新功能必须继承）

1. **不自动触达**：系统只产名单/素材/建议，对外动作永远顾问本人执行；
2. **证据强约束**：无来源/无证据不进库，拿不准标"推测"；
3. **数据不出本机**：评估/雷达/通话内容不进对外输出；restricted 层（费率/话术红线/禁挖名单）边界不松；
4. **禁挖名单**在所有名单类功能里生效；
5. **入库不开旁路**：候选人写库全走既有 preflight/commit/幂等/审计。

## 7. 协同纪律（多 Agent 同仓铁律）

1. 开工先 `git status`，他人未提交改动**不碰、不提交**；
2. `git add` 只写自己的具体文件名，**严禁 `git add -A` / `git add .`**（S6-4 曾因此卷入 S8 半成品，见 e327cac 提交说明）；
3. 共享文件（service.py/app.py/api.ts/llm.py）只**追加式**修改，不改既有行；
4. 提交信息与内容一致；部署统一走 `bash scripts/ship.sh`，部署后 `npm run generate:api` 补 api.d.ts 并单独提交；
5. 子任务超步数上限时优先提交可用基线（测试绿），规模可缩，红线不破。
