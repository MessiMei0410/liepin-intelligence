# ASA 实施 PRD（S9）：面试纪要助手——打完电话 3 分钟出纪要 + 画像更新

日期：2026-07-24
撰写：Kimi（顾问已确认立项，独立性强可插队）
执行方：Kimi CLI
优先级：P1（与 S7 并行不冲突；S9-1 不依赖任何未完成的模块）

---

## 0. 目标与定位

**解决的问题**：顾问每天大量候选人电话，核心价值都在通话里——动机、薪资期望、顾虑、时间线——但纪要靠手敲、画像更新靠记忆，知识沉淀严重流失。通用工具的 AI 面试是企业 HR 场景，不解决猎头的"电话后沉淀"。

**一句话目标**：通话结束后 3 分钟内，产出一份**结构化纪要 + 人才画像差异 + 下一步动作建议**，顾问确认后一键写回人才库。

**定位**：这是顾问个人的"第二大脑"，不是给客户看的文书系统。快、准、省事优先于格式漂亮。

## 1. 输入形态（三档，由简到全）

| 档 | 形态 | 场景 |
|---|---|---|
| ① 速记粘贴 | 顾问通话时随手记的几行字，打完粘贴进浮窗 | 立即可用，零门槛 |
| ② 口述复盘 | 打完电话对着 Copilot 浮窗口述 2 分钟（语音转文字） | 手上没记也能用 |
| ③ 音频导入 | 通话录音文件拖入（本地转写） | 信息最全 |

**S9-1 只做①，验证价值；②③在 S9-2。** 原因：音频转写涉及模型选型和算力，文字链路先把"纪要结构化和画像 diff"这个核心价值跑通。

## 2. 业务流程

```
通话结束 → 速记/口述/音频进入 Copilot 浮窗
 → 结构化纪要生成（六要素）：
    动机与诉求 / 薪资现状与期望 / 顾虑与障碍 / 决策时间线
    / 家庭与地域因素 / 顾问观察（语气、犹豫点、可信度）
 → 画像差异（diff）：与库内该候选人档案逐项对比，
    标出【新增】【变化】【矛盾】三类——矛盾项必须亮出来
    （如库里记"期望 40k"，今天说"50k 也可以谈"）
 → 下一步建议：跟进行动 + 建议时间点（接 S7 雷达信号更佳）
 → 顾问确认 → 写回：纪要存 call_note artifact；
    画像 diff 逐项由顾问勾选后写库，不自动覆盖
```

## 3. 数据模型

新 artifact 类型 `call_note`（schema_version `note_v1`）：

```json
{
  "schema_version": "note_v1",
  "candidate_id": 0, "job_id": 0,
  "input_type": "quicknote|dictation|audio",
  "raw_input_ref": "速记原文/音频文件哈希（音频本体不出本机）",
  "summary": {
    "motivation": "...", "comp": {"current": "...", "expected": "..."},
    "concerns": ["..."], "timeline": "...",
    "family_geo": "...", "consultant_observation": "..."
  },
  "profile_diff": [
    {"field": "期望薪资", "type": "new|changed|conflict",
     "old": "40k", "new": "50k可谈", "applied": false}
  ],
  "next_actions": [{"action": "...", "suggested_when": "..."}],
  "created_at": "..."
}
```

约束：`profile_diff[].applied=false` 的项**绝不写库**；写库走现有候选人更新链路（幂等+审计），不开旁路。

## 4. 红线

- 音频与原始口述**不出本机**：转写优先本地方案（whisper.cpp 或同等），如用 API 必须先过"脱敏段"（姓名/公司/薪资数字替换后再外传，回来再映射回）——选型时两种方案都要给出，顾问定。
- 画像写库必须逐项人工勾选，无"全部应用"的一键默认（防误覆盖）；矛盾项默认不勾选。
- 纪要内容属 restricted 邻近层：不进任何对外输出；推荐报告引用通话信息时由顾问手动摘取。
- 录音合规：音频导入功能首次使用时提示一次"请确认通话记录符合你的执业惯例"，不阻断、不录音——系统不主动录任何音。
- 文案业务语言：profile_diff →「画像有什么变化」；conflict →「和之前说的不一样」。

## 5. 分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| S9-1 | 速记粘贴 → 六要素纪要 + 画像 diff + 下一步建议（浮窗内闭环，写库走勾选确认） | 用 3 段真实通话速记（顾问提供）测试：纪要六要素齐全、diff 正确识别新增/变化/矛盾；顾问评价"比手敲省多少时间"；未勾选项零写库（契约测试） |
| S9-2 | 口述复盘 + 音频导入（转写方案两种选型报顾问定） | 5 分钟音频转写准确率可用（人名/公司名/技术词正确率抽验）；脱敏方案经顾问确认 |
| S9-3 | 接 S6：新通话信息触发该候选人重评估；接 S7：雷达信号与下一步建议联动 | 通话写库后 assessment 自动更新动机维度并标注"依据 X 月 X 日通话" |

每期独立 commit；门禁 L1 + 契约测试 + 真实速记/音频验收。

## 6. 度量

- 纪要产出耗时（目标 < 3 分钟，vs 手敲 10-15 分钟）
- 画像更新率：有通话的候选人中，画像字段 30 天内有更新的比例（当前基线极低）
- 矛盾捕获数：diff 发现的"和之前说的不一样"条数——这是直接影响成单的情报

## 7. 依赖与边界

- 依赖：Copilot 浮窗（已有）、候选人更新链路（已有）；S9-3 依赖 S6 评估器（已上线）。
- 不做：实时通话辅助（那是求职者工具的方向，猎头通话要的是真诚不是话术）；自动拨号/外呼（红线，不碰）。
