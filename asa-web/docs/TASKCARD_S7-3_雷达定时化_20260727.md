## 本期范围（三件事）

1. **信号过期降权**：signals 增加有效期机制——默认 60 天；生成榜单（ranking）和动机维度注入时，过期信号权重 ×0.2 且不再单独成为上榜理由；扫描时新信号与未过期旧信号按 (company, type, 规范化 summary) 去重合并，as_of 取最新。**既有 artifact 重算榜单即可验证，不用改历史数据。**
2. **周报生成器**：`POST /api/v1/radar/weekly-report` 生成 markdown 周报（本周新信号 Top N、信号过期 N 条、榜单变化 vs 上周：新进榜/掉出/升降、建议动作汇总）到 `work/radar/`；`GET /api/v1/radar/weekly-report/latest` 读取。周报文案全业务语言。
3. **Copilot 周报推送**：周报生成后写入 Copilot 仲裁层一条提醒（复用现有 publishCopilotContext 服务端通道）："本周雷达周报出了：X 家新信号，Y 家建议发起 Mapping"，顾问点开即看榜单页。不弹窗、不打扰，只是浮窗内一条消息。
4. **定时化（主代理负责，不在本卡代码范围）**：仓内提供 `scripts/radar_weekly_scan.py` CLI 入口（扫描+过期降权+周报一条龙，退出码非零即失败），主代理用 Blueprint Automation 建周度定时任务调它。

## 红线

- 过期是"降权"不是删除，历史信号保留可查；
- 周报内容全部来自库内 artifact，不现编；榜单变化对比基于前后两期 artifact，缺上周则如实标注"首期，无对比基线"；
- Copilot 推送不含敏感细节（只推条数和入口，不推具体人名/公司负面）；
- 定时任务调度限速 ≤1 QPS（S7-1 已发现百度反爬），扫描窗口避开白天高峰（建议工作日早 7-8 点）。

## 验收标准

1. 过期降权：构造/挑选一条 60 天前的信号 → 榜单重算后该公司排名下降且该信号不再列为上榜理由；未过期信号不受影响；
2. 周报真出一份：包含本周 Top 信号 + 变化对比（首期无基线时正确标注）；markdown 落在 `work/radar/`；
3. Copilot 浮窗出现周报提醒消息；
4. CLI 入口单跑成功（扫描+周报一条龙），退出码 0；
5. 契约测试：过期计算边界（59/60/61 天）、去重合并、周报无基线分支、CLI 失败退出码。

## 门禁层级

- L1 `npm run ci:fast` + L2 `npm run test:contract` 必过；
- 真实验证：验收 2/3/4 真跑。
