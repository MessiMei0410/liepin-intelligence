## 本期范围（backend-only，不做 UI）

1. **artifact 模型**：新类型 `candidate_assessment`（schema_version `assessment_v1`，键 = candidate_id × job_id），字段按 PRD §3——但本期只实现 `trajectory` 和 `move_history` 两个维度，其余维度字段留空占位（S6-2/3 填）。
2. **轨迹评估器**：输入候选人简历/结构化数据 + strategy_v2 + 公司图谱（雇主 tier、团队），输出：
   - `trajectory`：每段经历含金量（公司 tier/团队/汇报线）、晋升速度快慢、技术栈演进判定（上升/平移/吃老本）；
   - `move_history`：逐次跳槽方向判定（up/lateral/down，平台/title/职责三维）+ 当前这单对他是升是平。
3. **证据强约束（硬）**：每条 verdict 至少挂一条 evidence；evidence 类型为"简历"时必须引用该候选人数据中**逐字存在**的片段（契约测试做原文包含校验），类型为"图谱/知识库"时必须引用真实条目 ID；挂不上证据的判断必须标 `confidence: inferred`。
4. **回放工具**：脚本从 v3 库按岗位抽历史人选（三个 case 对应岗位各 5 人，成单/未成单混合），批量生成评估，导出一份**给人看的** markdown（每人一段：轨迹结论 + 跳槽史 + 证据 + 置信度），供顾问盲评。导出文件放 `work/assessment_replay/` 不进 git。
5. **接口**：`POST /api/v1/candidates/{id}/assessments?job_id=`（生成/重新生成）+ `GET` 读取；幂等（同人同岗重复 POST 更新不重复建行）。本期不接推荐报告、不接 Copilot。

## 红线（写死）

- 评估只辅助不决策；verdict 里不得出现"建议淘汰/不建议推荐"类字眼，风险类表述留到 S6-3。
- **敏感属性负向扫描（契约测试）**：年龄、性别、婚育、户籍不得作为负面因子出现在任何 verdict/evidence 摘要里。
- 证据编造 = 返工：引用的简历片段必须逐字存在于该候选人数据；图谱引用必须真实存在条目。
- 评估数据不出本机；回放导出含简历内容，只进 `work/`（gitignore），不进 git、不外发。
- 文案业务语言（UX-1 原则）：trajectory→「职业轨迹」、move_history→「跳槽质量史」、inferred→「推测」。

## 验收标准

1. 回放跑通：三个 case 岗位各 5 个历史人选生成评估，markdown 导出完整；每人轨迹+跳槽史都有结论、有证据、有置信度。
2. 证据契约测试：随机抽 20 条 evidence 类型"简历"的引用，逐字包含校验 100% 通过；故意构造一条编造引用 → 必须被测试拦住。
3. 敏感属性负向扫描通过（构造含"已婚已育稳定"类诱导输入 → verdict 不得采纳为因子）。
4. 幂等测试：同人同岗重复 POST，库中只有一条 artifact，as_of 更新。
5. 顾问盲评（验收的最后一步，由顾问本人做）：读回放 markdown，对每份评估打"像/不像资深顾问写的"，结果直接回复给主代理记录。**盲评通过率不达标不进入 S6-2**，改 prompt/维度口径后重跑。
