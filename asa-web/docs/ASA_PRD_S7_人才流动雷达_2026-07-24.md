## 0. 目标与定位

**解决的问题**：资深猎头知道"什么时候打这个人"——财报暴雷后、组织调整后、股权激励没覆盖到、年终奖到账后。这是成单率最高的触达时机，但目前 ASA 只能被动等岗位驱动。

**一句话目标**：定期扫描目标公司池的公开信号，输出一份**"这周该打谁"的优先级榜单**——哪家公司的人现在最可能动、为什么、建议打哪个团队——并联动 Mapping 直挖和寻访策略。

**与通用工具的差异**：市面上的"人才雷达"多是简历库活跃度信号（谁更新了简历）；ASA 的雷达扫的是**公司侧事件信号**（组织/资本/激励/订单），这是猎头真正的信息优势来源。

## 1. 信号体系（六类，全部公开信息只读）

| 信号 | 判断逻辑（对人才流动的含义） | 来源 |
|---|---|---|
| **财报/业绩预告** | 利润下滑/亏损 → 骨干观望；超预期 → 扩编（卖方时机） | 公告、财经媒体 |
| **融资/IPO 进展** | 新融资到位 → 扩编窗口；IPO 辅导期 → 员工兑现预期（留人强）vs 辅导停滞（走人） | 公告、媒体 |
| **股权激励/员工持股** | 锁定面窄 → 未覆盖骨干是动因人群；解锁期到 → 兑现后可动 | 公告 |
| **组织/高管变动** | 新 VP/CTO 上任 → 团队重组窗口；核心人物离职 → 其旧部可挖 | 官网、公众号、媒体 |
| **招聘异动** | 挂牌量骤降（收缩）/ 激增（扩编）；新业务线岗位出现（战略转向） | 猎聘/BOSS 公开挂牌（只读） |
| **风险事件** | 裁员传闻、欠薪、失信被执行、大客户流失 → 全队可挖 | 公开信用平台、媒体 |

每条信号必须带：来源 URL、as_of 日期、涉及公司、信号类型、对人才流动的解读（一句人话）、置信度。**无来源的信号不进库（防编造，同 mapping 硬约束）。**

## 2. 业务流程

```
每周扫描（首期手动触发，S7-3 定时化）
 → 公司池 = 589 图谱 + 33 客户档案 + mapping_task 已确认团队所在公司
 → 信号采集（六类，只读）→ radar_signal artifact 入库
 → 榜单生成：公司×信号强度×在手岗位相关性 排序
 → 顾问视图：本周榜单（公司、信号、建议动作：发起 Mapping / 激活存量人选 / 观望）
 → 联动：
    - "发起 Mapping" → 直接创建 mapping_task（trigger=radar）
    - "激活存量" → 筛出人才库中该公司的人，提示顾问触达（动作仍由顾问执行）
    - 信号注入 S6-2 动机维度（该公司的人评估时带上近期信号）
```

## 3. 数据模型

新 artifact 类型 `radar_scan`（schema_version `radar_v1`）：

```json
{
  "schema_version": "radar_v1",
  "scan_date": "2026-07-24",
  "signals": [
    {"company": "芯源微", "type": "org_change|earnings|funding|equity|hiring|risk",
     "summary": "北方华创控股整合中，沈阳↔北京团队协同",
     "implication": "骨干观望期，Track/清洗人才可挖",
     "source_urls": ["..."], "as_of": "2026-07-24",
     "confidence": "high|medium|low", "linked_action": "mapping|activate|watch"}
  ],
  "ranking": [{"company": "...", "score": 0, "reason": "..."}],
  "stats": {"companies_scanned": 0, "signals_found": 0, "sources_failed": 0}
}
```

信号有效期：默认 60 天，过期信号自动降权不进榜单（事件有时效，财报信号不能管半年）。

## 4. 红线

- 全部公开信息只读；不破解、不碰登录墙后的非公开数据；脉脉类来源不做。
- 不自动触达——雷达只出榜单和理由，所有对外动作由顾问执行。
- 信号必须有来源 URL + 日期；解读（implication）是推测，UI 标注。
- 风险事件类信号表述克制：写"公开招聘平台显示挂牌量下降"，不写"这家公司要完"——避免顾问拿着未经证实的话去跟人选说。
- restricted 层边界不变：禁挖公司照常过滤；费率不出现在任何输出。

## 5. 分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| S7-1 | 信号采集器 + radar_v1 schema + 榜单生成（手动触发，公司池先限 33 家客户档案 + mapping 已确认公司） | 真跑一次：≥20 家公司扫完，每条信号带来源 URL；编造检查契约测试（无来源信号写入被拒）；榜单 markdown 输出到 `work/radar/` 供顾问抽验 |
| S7-2 | 联动：榜单→发起 Mapping（trigger=radar）、激活存量人选筛选、信号注入 S6 动机维度 | 从榜单点"发起 Mapping"能建 mapping_task 且团队建议带上信号上下文；某公司信号出现在其候选人的动机维度 evidence 里 |
| S7-3 | 定时扫描（接 Blueprint Automation 周度任务）+ 信号过期降权 + Copilot 周报推送 | 周度自动跑、榜单进 Copilot 浮窗；过期信号不进榜 |

每期独立 commit；门禁 L1 + 契约测试 + 该期真实扫描验收。

## 6. 度量

- 信号驱动触达 vs 无信号触达的回复率对照（雷达价值的终极验证）
- 榜单采纳率（顾问对"建议动作"的执行比例）
- 信号有效率（60 天内被验证为真影响的比例，顾问可标记"这条信号靠谱/不靠谱"，回流校准）

## 7. 依赖与边界

- 依赖：589 图谱、33 客户档案、S5 mapping、S6-2 动机维度；S7-3 依赖 Blueprint Automation（周度 cron job）。
- 不做：简历库活跃度信号（猎聘那边已有，不重复造）；人选级实时监控（那是 S8 定价与成单预判的数据层）。
