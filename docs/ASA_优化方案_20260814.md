### P2-2 前端 bundle 瘦身

**现状**：优化前主 chunk 约 806 kB（gzip 234 kB），已完成第一阶段分包。

**方案（按收益/风险排序）**：
1. **低风险**：`api.d.ts`（6292 行）是类型声明，改 `import type` 全量引入为按需——Vite/TS 应自动 tree-shake，先验证是否真的进 bundle（若已摇掉则跳过）。
2. **中风险**：React 19 + react-markdown 拆 vendor chunk（`manualChunks`），主 chunk 从 803 kB 降到 ~500 kB 内。
3. **中风险**：懒加载非首屏模块——`AgentWorkspace` 之外的页面（AnalysisWorkspace/Candidates/Jobs/Radar 等）改 `React.lazy` + Suspense。
4. **验证**：每次改动跑 `ci:fast` + functional E2E；截图基线只在 UI 可见变化时重生成。

**当前结果**：Vite 8/Rolldown 使用函数式 `manualChunks` 拆出 `vendor-react`、`vendor-icons`、`vendor-markdown`、`vendor-validation`；主应用 chunk 降至约 375 kB（gzip 104 kB），构建不再出现单 chunk 超 500 kB 警告。首屏 LCP 仍需在真实浏览器网络条件下单独采样，不能由构建体积单独推断。

**后续**：继续评估 App 内非首屏业务页的懒加载，但需配合真实导航/截图回归，避免把四个主 tab 的首次打开行为变成空白等待。

### P2-3 前端 lint warning（低优先）

9 个 warning 在 `.prettierignore` 存量压缩 JSX（WorkflowPanel ×6 + WorkflowCandidates ×3）。**仅当决定解压缩这两个文件时一并修**（set-state-in-effect 改派生状态/回调、exhaustive-deps 补依赖）；解压缩需先确认不破坏契约测试正则（`tests/test_candidate_action_dialog.py`）。

### P2-4 测试提速

- 16 个测试文件在线复制 1.3GB 正式库 → 单测 10–20 分钟。**方案**：
  1. 建**精简测试库**（只保留被测客户/岗位/候选人的 schema + 子集数据，几百 KB 级），fixture 从精简库复制；交接档案已有"精简库缺少候选人辅助表时降级为空匹配"的先例可参考。
  2. 或对只读型测试用 SQLite `mode=ro` 直接连正式库（不复制），写型测试才复制——用 `tmp_path` 做差异副本。
- CI 上 `--ignore` 三个最慢文件（P0 已含），本地全量回归保留。

**验收**：全量 pytest 从 16 分钟降到 <5 分钟；三个慢测试文件有对应提速说明。
