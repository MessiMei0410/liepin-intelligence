## 2. 优化方案（根因 → 措施 → 验收）

### 2.1 新增措施（本方案提出，不在既有 PRD 内）

**N1 渠道查询方言层**（治 F1，P0）
- 在策略对象 `step4_keyword_groups` 与渠道 runner 之间加一个**逐渠道查询构造器**：同一组画像关键词，猎聘输出组合查询（公司+职能+技术词），X-SaaS 按其搜索语义拆分为单字段查询（公司词独立查询 / 职能词独立查询，逐条执行再合并去重）。
- 每个渠道一个 `query_builder` 模块 + 契约测试：输入种子 JSON 的关键词组，断言输出符合该渠道语法（如 X-SaaS 单查询不得含 ≥2 个公司名）。
- 验收：用士兰微种子重放，X-SaaS 查询不再出现多关键词拼接；下一轮真实寻访 X-SaaS `recall_count > 0` 或归因明确为 `no_results`。

**N2 0 归因升级**（治 F2，P0，小改动）
- `classify_zero_result` 增加两类：`query_build_error`（查询含异常拼接模式/空查询/渠道语法违规）与 `pool_saturated`（召回正常但排重率 >90%）。
- 契约测试覆盖第 7 轮的真实形态（嵌套拼接 → query_build_error）。

**N3 池枯竭信号与扩池决策树**（治 F3+B1，P0，业务价值最大）
- 每轮结束计算 `dedupe_rate`；>80% 触发"池枯竭"信号，复盘器输出按序决策树（每步可顾问确认）：
  1. 换关键词组（同池不同词：技术词↔公司词↔职能词轮换）
  2. 扩池：T1 → T2（客户整机厂）→ T3（相邻池，士兰微 v1.1 已授权启用）
  3. 放宽条件（年限/职级/地点，逐项放宽并记录代价）
  4. 渠道再平衡（见 N4）
  5. 提示顾问：该岗位本地池+渠道池已尽，建议转 Mapping 直挖或与客户校准方向
- 决策树写进 `strategy_review` artifact，前端"调整条件再搜"展示为可选步骤而非空白输入。
- 验收：构造排重率 >80% 的测试工作流，复盘 artifact 输出有序决策树；#154 第 8 轮复盘不再出现"原样重搜"。

**N4 渠道效能学习**（治 B2，P1）
- 按 `渠道 × 岗位原型` 累积命中率（召回→入库→高分转化率），存入知识库；连续 2 轮 0 召回且归因非渠道故障的组合自动降权（查询配额让给高效渠道），降权决策在策略对象中留痕。
- 验收：X-SaaS × tme_computing_power 的累计数据可见；降权建议出现在复盘 artifact。

**N5 评估标准校准暴露**（治 B3，P1）
- 高分率 0 且评估数 ≥5 时，复盘器附"评估尺度复核"条目：抽取 3 个被否人选的评分证据链摘要给顾问一键复核（"是尺严还是人不行"），顾问结论写回评估校准参数。
- 验收：#154 现有 6 位评估人选可一键调出证据链。

**N6 策略全要素消费检查**（治 B4，P1）
- 策略生成后自检：种子的 T1/T2/T3 池、地点策略、排除规则是否全部进入 `strategy_v2`；缺项在顾问确认页显式列出"未使用：T2 客户整机厂、杭州优先"，防止知识资产静默漏用。
- 验收：用士兰微种子重放，T2/地点策略出现在策略对象。

## 3. 目标架构（寻访链路 v2）

```
岗位 → 输入分级(L1/L2/L3) → 五步判断树(策略v2)
      → 排除规则引擎(五类清单+禁挖名单)
      → 渠道查询方言层(猎聘语法 / X-SaaS 语法)   ← N1 新增
      → R3 审批 → 渠道执行 → 漏斗落库
      → 复盘器: 策略错vs执行错 + 池枯竭信号      ← N2/N3 增强
      → 扩池决策树(换词→扩池→放宽→渠道→人工)    ← N3 新增
      → 渠道效能学习 + 评估校准                   ← N4/N5 新增
      → 回放评测(指标不退) + 横向萃取入知识库
```

每一环都有信号、有归因、有下一步——不再有"步骤全绿但不知道为什么没人"的状态。

## 4. 治理：终结"一点一点修"

1. **根因看板**：本文 §1 的根因表作为唯一看板，新出现的问题先归根因再定措施，禁止绕过看板做点状修复。看板维护在 `docs/`（本文档），每次修复更新状态列。
2. **修复必须带防回归契约**：每个 N 项措施配契约测试（N1/N2 已给出具体断言），没有契约的修复不允许合入——这是今天 X-SaaS 条件重置这类修复已验证有效的做法，推广为强制。
3. **每周一次数据复盘**：用漏斗表看三张图——排重率趋势、渠道 0 归因分布、高分率趋势。趋势不对的根因进看板，而不是等问题爆出来。
4. **真实寻访即验收**：每个 N 项落地后用 #154（或活跃岗位）跑一轮真实验证，数据写回复盘 artifact——第 5、7 轮已经是这个模式，固化下来。
