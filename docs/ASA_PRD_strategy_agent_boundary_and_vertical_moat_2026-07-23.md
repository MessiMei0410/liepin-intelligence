# ASA 产品优化 PRD（战略层）：Agent 化边界 × 垂直壁垒

日期：2026-07-23
撰写：Kimi
定位：本文是产品战略 PRD，回答"ASA 该长成什么样"；工程落地拆解另出实施 PRD（参考已有的业务终态/渠道漏斗 PRD 模式）。
读者：产品所有者（资深半导体猎头）+ 执行 Agent（Kimi CLI 等）

---

## 0. 核心判断（先给结论）

1. **ASA 的壁垒不在"自动化"，而在"把资深顾问的判断形式化 + 把半导体行业知识资产化"。** 数据库规模、自然语言搜索、自动触达这些维度上，Juicebox（800M+ 简历）、hireEZ、SeekOut、递航、脉脉高聘已经卷成红海，ASA 不可能也不应该正面竞争。
2. **Agent 化的正确边界是"判断密集型环节留人，执行密集型环节给 Agent，草拟型环节人机共写"。** 边界划错有两种死法：自动化过头（渠道封号、候选人体验崩、错推损害口碑），或者自动化不足（产品退化成又一个 ATS 壳）。
3. **寻访策略 Agent 是产品的心脏。** 士兰微 #154 连续 3 轮"步骤全完成但合格人数不足"，暴露的不是执行力问题，而是策略迭代没有闭环——这正是资深顾问和关键词匹配工具的分水岭。
4. **个人垂直知识库是时间的朋友。** 每一次寻访、复核、停止、客户反馈都在沉淀只有这个顾问才有的数据资产，用得越久壁垒越深，通用工具无法复制。

## 1. 产品/流程设计：Agent 化边界

### 1.1 全流程分级表

按"判断密度 × 可逆性 × 对外代表性"三个维度，把猎头全流程划成四级：

| 环节 | Agent 化等级 | 说明 | ASA 现状 |
| --- | --- | --- | --- |
| JD 解析 / 岗位诊断 | **A 全自动** | 结构化硬性要求、核心能力、卖点；人只做校准确认 | 已有（岗位详情含硬性要求/核心能力/卖点） |
| 历史人才库排重 | **A 全自动** | 纯数据操作，零判断 | 已有 |
| 寻访策略生成（目标公司/关键词/排除/放宽预案） | **B 草拟+人校准** | 判断密度最高环节，见第 3 章 | 半自动：策略由 LLM 生成但缺行业知识与迭代闭环 |
| 多渠道召回 / 详情抓取 / 入库 | **A 全自动（带 R3 审批闸）** | 执行密集，必须全自动才有杠杆 | 已有，审批链路成熟 |
| 简历初筛 / 完整性校验 | **A 全自动** | 规则明确（complete 才入库） | 已有 |
| 候选人评估打分 | **B 草拟+人复核** | Agent 出分+证据链，人复核边界人选；评分标准随客户口味学习 | 已有评估，缺"证据可读性"和客户口味学习 |
| 复核通过 / 停止推进 | **C 人决策，Agent 一步记录** | 业务判断归人，记录成本归零 | 已有（Copilot 短指令一步写入，业界领先） |
| 触达文案生成 | **B 草拟+人发送** | Agent 按人选背景个性化，人审后发；**批量个性化≠批量发送** | 未做 |
| 人选沟通 / 意向判断 / 薪酬谈判 | **D 纯人** | 关系资产核心，AI 代聊是口碑毒药；Agent 只做事实记录与提醒 | 正确地未做 |
| 推荐报告生成 | **B 草拟+人定稿** | Agent 按客户偏好格式生成，人把关评价措辞 | 未做 |
| 客户反馈跟进 / 面试安排 | **C 人主导，Agent 记录** | | 部分（事件记录） |
| 已读不回唤醒 | **C 人决策，Agent 提醒+给话术选项** | 递航等竞品做 AI 自动复聊——**不建议跟进**，中高端人选对机器人触达敏感 | 已读不回可一步记录，唤醒动作未做 |

### 1.2 三条边界原则

1. **可逆性原则**：不可逆动作（对外触达、状态终止、推荐给客户）必须有人工确认点。ASA 现有的 preflight/commit + 一次性 token + R3 审批已经是正确范式，新增任何写动作沿用，不开后门。
2. **关系资产归人原则**：凡是候选人有感知、能识别"对面是不是人"的环节，第一触点以后必须是人。Agent 可以准备弹药（文案、人选背景摘要、谈薪数据），不扣扳机。
3. **判断显式化原则**：Agent 做的每个判断（评分、排除、策略选择）必须带可追查的证据链，让人能一眼校验"它为什么这么判"。判断不可解释的自动化等于把品牌交给黑盒。

## 2. 技术架构演进参考

### 2.1 现状盘底

ASA 现有架构（本机 SQLite 唯一事实源 + FastAPI Core + 工作流状态机 + 渠道 runner + Copilot）在"个人工作台"尺度上是健康的。**不建议推翻，只做加层。** 三个值得投入的演进方向：

### 2.2 人才库结构化：从"简历文本库"到"人才资产图谱"

现状：简历抓得很完整（full_text/work/project/education 强制 complete），但检索与评估仍主要依赖文本和规则。

演进：在 v3 库之上加一个**结构化人才画像层**（不动现有表，新建映射表）：

- 每人选抽取：`技能本体标签`（如 功率半导体/AC-DC 拓扑/PFC/LLC/SiC/GaN/车规 AEC-Q101）、`产品线经验`、`公司-团队-汇报线`、`职级标定`、`薪酬带`、`活跃信号`（简历更新时间、跳槽周期）。
- 技能本体先做**半导体垂直小本体**（几百个节点，手工种子+Agent 维护），不建通用大本体——小本体精准度碾压大本体。
- 身份解析继续强化现有指纹/遮罩名合并体系，把"同一个人在猎聘、X-SaaS、历史库"的实体对齐做成一等能力。

### 2.3 RAG：行业知识库增强判断，而非替代判断

适用点（按价值排序）：

1. **评估增强**：评估候选人时检索岗位知识（如"PC电源市场岗需要什么背景"）+ 类似岗位历史评估案例，给出带引用的评分理由。
2. **策略增强**：生成寻访策略时检索公司图谱（见 4.2）与历史策略复盘。
3. **顾问问答**：Copilot 回答"这类岗位市场上什么行情"时引用知识库，而不是模型裸答。

实现约束：本地优先（现有架构全是本机，简历含 PII，**Embedding 与检索必须本地完成**，不送第三方向量服务）；先结构化检索（SQL/本体匹配）后向量检索，能用确定性查询解决的不用向量。

### 2.4 多 Agent 分工：纵向专业化，不搞横向热闹

现状是单一 A System Agent + 工作流步骤制。建议演进到**四个纵向角色**，但仍由状态机编排（不搞自由对话式多 Agent——交接文档已证明可靠性来自状态机与工具契约）：

| 角色 | 职责 | 落地方式 |
| --- | --- | --- |
| 策略 Agent | 寻访策略生成与迭代（第 3 章） | 现有策略生成步骤的专业化 |
| 评估 Agent | 候选人打分+证据链 | 现有评估步骤增强 RAG |
| 知识库 Agent | 维护公司图谱/技能本体/薪酬带，从每次寻访结果中抽取沉淀 | 新增，后台低频运行 |
| 文案 Agent | 触达话术/推荐报告草拟 | 新增，人审后发 |

### 2.5 数据源对接

- **猎聘/X-SaaS**：维持现有正式 runner + 审批 + OpenCLI 影子对照，不激进迁移。风控是生死线，世纪云猎那类"视觉语义绕过风控"的打法对个人账号资产风险过高，**明确不跟进**。
- **脉脉**：作为**只读情报源**（公司动态、人才流动信号、组织架构线索），通过浏览器登录态读取公开页面，不做自动触达。脉脉的社交数据正是它回复率高的原因，也是我们最不该自动化的渠道。
- **公开信号源**：公司官网/公众号/招聘 JD（判断团队在扩什么方向）、专利/论文（判断技术线）、融资新闻（判断扩张节奏）——这些喂给知识库 Agent，是 Mapping 深度的原料，合规且免费。
- **合规红线**：简历 PII 只存本机；遵守平台 ToS；《个人信息保护法》下候选人数据的保存与使用限于招聘目的，知识库只沉淀行业/公司层信息，不沉淀与招聘无关的个人敏感信息。

## 3. 工作流打磨：寻访策略 Agent（本 PRD 核心）

### 3.1 问题定义：为什么现在的策略是"泛泛的关键词匹配"

士兰微 #154 案例复盘（真实数据）：岗位是"技术市场经理/总监（PC电源）"，目标 20 人。三轮寻访，第 2 轮合格不足，第 3 轮 X-SaaS 六组关键词召回 0、猎聘 5 人全待核验、0 高分。第 3 轮目标里已有人工放宽（"年限放宽至 5 年以上，职级放宽至资深工程师/主管"）——说明**放宽动作靠人盯，系统没有主动诊断"为什么找不到"并给出下一步**。

一个资深半导体顾问拿到这个岗位，脑内跑的是这样的判断（示例，需你校准）：

> 士兰微是 IDM 功率半导体原厂，"技术市场经理（PC电源）"本质是做电源厂客户的技术型市场/产品定义。目标人选三类：① PC 电源厂（台达、光宝、航嘉、长城、全汉、康舒等）的 PM/技术岗，懂电源拓扑和客户端需求；② 功率半导体友商（英飞凌、安森美、ST、华润微、新洁能等）的 FAE/市场，懂器件懂应用；③ 有大客户对接经验的器件代理/方案商技术市场。关键词不该锁"PC电源"字面，而该锁 AC-DC、PFC、LLC、拓扑、电源方案这些技术词 + 目标公司池。

而当前系统的策略生成是"JD 文本 → LLM 生成关键词组"，缺三样东西：**目标公司池的显式判断、相邻职能的展开逻辑、每轮结果对策略的反馈**。

### 3.2 设计：结构化判断树 + LLM 填充，而非自由 Prompt

策略生成从"一段 prompt 出关键词"升级为**五步显式判断**，每步留痕、可被顾问逐条推翻：

1. **岗位本质定位**：这个岗位在客户价值链里是什么角色（技术/市场/管理/交付），向谁汇报，服务什么客户/产品。→ 输出一段"岗位本质"陈述，展示给顾问确认。
2. **目标公司池（分层）**：T1 直接竞对/同类公司、T2 上下游相邻（客户、供应商、方案商）、T3 可迁移行业。每层给公司名单 + 入选理由。→ 接行业知识库（4.2），知识库没有的公司标记"待补录"。
3. **人选画像展开**：每类目标公司对应的目标职能/职级映射（不同公司职级体系不同，如"总监"在台达和在新洁能含金量不同）。
4. **关键词组与排除规则**：每组关键词绑定"它要打哪类画像"，排除规则显式列出（行业不放宽/排除某些公司）。
5. **预期与放宽预案**：预估每层召回量级，预案写明"若 T1 召回 < X，则放宽 Y 条件"。→ 这直接喂给"调整条件再搜"按钮。

LLM 在每一步内部做生成，但**步骤结构、目标公司池、放宽预案是结构化数据**，存进工作流策略对象，可 diff、可复盘。

### 3.3 迭代闭环：策略复盘器

每轮寻访结束后，自动产出策略复盘（数据全有：`agent_sourcing_funnel` 漏斗 + 0 归因 + 评估结果 + 停止原因）：

- **诊断**：是策略问题还是执行问题？（X-SaaS 召回 0 且归因 `no_results` → 渠道不覆盖该人群；猎聘召回多但高分 0 → 画像偏了；召回就少 → 关键词太窄或池子本身小）
- **建议**：给出下一步的具体修订（换关键词组/展开 T2 公司池/放宽某条件/换渠道权重），以 diff 形式呈现，顾问一键采纳或修改。
- 这就是"调整条件再搜"按钮的脑子：点开后不是空白输入框，而是这份复盘建议。

### 3.4 让系统学习"你的直觉"

- 每次顾问推翻/修改 Agent 的判断（改关键词、停掉 Agent 看好的人、通过 Agent 看漏的人），都作为 `explicit_corrections` 学习信号沉淀（机制已存在，需要策略层真正消费）。
- 按"客户 × 岗位类型"积累策略记忆：同样是市场岗，士兰微的口味和另一家设计公司不同，策略 Agent 应该越用越像"你的副手"，而不是通用 sourcer。
- **评测**：用历史真实寻访 case 建回放评测集——给定岗位，对比 Agent 策略与当年实际成单路径的差距。每次改策略逻辑跑回放，防止越改越差。

## 4. 差异化思考：壁垒建在垂直知识库与 Mapping 深度

### 4.1 市场格局（2026-07 检索核实）

- **海外**：Juicebox/PeopleGPT（800M+ 简历，$139-199/seat/月）、hireEZ（$169-250/人/月）、SeekOut（企业级，中位约 $20k/年）、Findem、Fetcher——共同打法是"数据库规模 + 自然语言搜索 + 触达自动化"。
- **国内**：递航（端到端闭环：寻访+AI 意向沟通+邀约面试，主打"替代真人"）、脉脉高聘（社交数据资产，被动候选人触达与回复率优势）、猎聘自身 AI 化、世纪云猎（视觉语义绕过风控）、谷露（猎头 ATS）。
- **趋势**：语义匹配替代关键词、RAG+本体成为差异化卖点、"人才银行"数据资产被公认为护城河。

**结论**：通用赛道已是红海，且都在往"全自动替代人"叙事走。ASA 作为一个资深顾问的个人工作台，赢面只在三件事：**比你更懂半导体、比你更懂你的客户口味、比你更会复盘**。这三件事大公司做不了（没有你的数据），通用工具不屑做（市场太窄）。

### 4.2 核心资产：半导体行业知识库

分四层建设，全部本机存储，知识库 Agent 维护：

1. **公司图谱**：细分赛道（功率/模拟/MCU/存储/设备/材料/EDA/封测）× 公司 × 产品线 × 团队规模 × 关键人物线索。种子数据由你手工录入几十家核心公司，Agent 从公开信号源持续扩充。
2. **职级与薪酬带**：主要公司的职级体系映射（谁家的"资深工程师"相当于谁家的"主管"）、各赛道薪酬带——评估和谈薪的直接弹药。
3. **人才流动事件**：谁从哪跳到哪、什么时间在动（从寻访和公开信息中捕捉），Mapping 的动态层。
4. **岗位原型库**：每完成一个岗位，沉淀"岗位原型"（本质定位/目标池/有效关键词/复盘结论），下一个同类岗位直接复用迭代——**复利的载体**。

### 4.3 明确不做

- 不做数据库规模竞争（猎聘/X-SaaS 就是你的数据库接入层）；
- 不做 C 端候选人产品；
- 不做 AI 自动触达/自动复聊（中高端半导体圈子小，一次机器人触达的口碑损失大于十轮效率收益）；
- 不做通用行业版本，先让半导体+前沿科技一个垂直做到"离不开"。

## 6. 度量指标（成单导向，非技术导向）

- 寻访→复核通过率（策略准度的直接体现，当前士兰微岗约 0/6）
- 一轮命中率：首轮策略无需人工放宽即达标的工作流占比
- 渠道产出率：各渠道 召回→入库→高分 转化率（funnel 表直接算）
- 岗位关闭周期、推荐→面试转化率
- 知识库复用率：新岗位策略中复用既有原型/公司池的比例

## 7. 风险与边界

- **数据合规**：简历 PII 本机存储、不送第三方向量服务；知识库只沉淀公司/行业层信息。
- **平台风控**：不碰绕过风控的执行技术；猎聘/X-SaaS 自动化维持现有低频+审批模式。
- **模型依赖**：策略/评估能力绑定模型质量，换模型必须跑回放评测集（不是只跑交接文档那六项回归）。
- **过度 Agent 化**：多 Agent 分工是纵向专业化，不引入自由对话式协作；状态机和工具契约优先于"智能"。
- **知识库冷启动**：前 30-50 家公司需要你手工投入，这是壁垒的成本，绕不开；Agent 负责之后的扩与鲜。
