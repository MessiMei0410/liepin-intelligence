# ASA 功能模块总表

更新时间：2026-08-14

本表以当前单体仓库、ASA Core OpenAPI、Agent 能力注册表和 ASA App 实际入口为准。模块状态分为：

- `主入口`：ASA App 中可直接进入并完成核心动作。
- `内嵌入口`：附着在 Agent、岗位、人选或工作流详情中。
- `服务能力`：可由 Agent/工作流调用，但没有独立页面。
- `兼容入口`：用于审计、回滚或浏览器桥接，不作为主工作台入口。

## 一、主工作区

| 模块 | 入口 | 核心能力 | 当前打磨重点 |
| --- | --- | --- | --- |
| Agent 对话工作区 | 主入口 `Agent` | 多轮对话、业务焦点、对象卡、任务恢复、重试/停止、任务搜索/改名/归档 | 候选人证据链强制回读、上下文冲突提示、长对话与错误恢复 |

## 八、统一打磨基线

所有模块交付前统一检查：

1. 入口可达，返回路径明确，不依赖隐藏 URL。
2. 加载、空数据、部分失败、完全失败、重试五种状态完整。
3. 列表展示真实总量；分页、搜索和筛选不只作用于首屏样本。
4. 写动作必须有预检、幂等键、结果回读和冲突提示。
5. 工作流状态统一走 `statusMapping.ts`，完成态必须展示结果或明确说明无产物原因。
6. Agent 回答按“证据 -> 技术含义 -> 岗位要求 -> 判断边界 -> 核验问题”展开。
7. 桌面和 390px 窄屏无页面级横向溢出，固定区域不遮挡输入和操作。
8. 外部渠道动作保留 R3 单次审批，不绕过风控和人工确认。

## 十、第二轮已落地：寻访安全与结果同步

- “立即停止寻访”贯通工作流、当前分页和渠道子进程：取消后清空恢复游标，并终止当前猎聘/X-SaaS/OpenCLI 子进程，不再只阻止下一批。
- 专业电源岗位禁止把目标公司单独作为查询词；公司定向必须绑定 VPD、VRM、TLVR、多相 Buck、DrMOS 或模块电源能力词，且只在支持组合语义的猎聘执行。查询计划最多 32 个单元、优先 12 家高价值公司，避免公司与关键词笛卡尔扩展召回整家公司销售、商务、汽车和 FAE 人群。
- 专业电源岗位执行前使用更严格分数门槛，低于 70 分的渠道结果在正式入库前拦截；原始召回仍保留在证据台账供审计。
- 猎聘命中安全风险、合规墙、人机验证或访问频繁后，硬停止猎聘及后续分页，不再启动 OpenCLI 影子读取；步骤详情展示明确的风险停机原因。
- Agent 会话中的工作流对象卡对活动状态持续同步，进入已完成、已取消或失败终态后立即更新并停止轮询，避免详情已结束而对话仍显示旧状态。

## 十一、第三轮已落地：结果产物与评估重生成

- 工作流“结果与产物”从静态文字恢复为可点击入口：Markdown/JSON 可站内查看，文件与长正文可下载，产物类型和校验状态统一显示中文。
- Core 新增受限产物详情与下载接口。文件下载只允许数据库同级 `asa_artifacts` 目录；数据库记录中的任意外部路径、路径穿越和符号链接越界均不可读取。内容型产物由 Core 直接生成下载响应。
- 工作流没有文件产物时，根据计划中、执行中、取消、失败、评估回写和状态更新分别解释结果去向，不再只显示“暂无执行产物”。候选人批量核验明确说明结果已写入评估记录。
- 工作流首屏不再内联完整查询计划、候选简历、审批快照、事件详情和产物 metadata。士兰微旧寻访工作流详情由约 11.9 MB 降至约 51.6 KB；完整步骤审计仍通过按需详情接口读取。
- 人选详情“重新评估”显式发送 `force=true`，真正生成并覆盖当前评估版本；首次“做评估”仍复用输入指纹缓存策略。前端成功回执区分“已生成”和“已重新生成”。
- 停止候选人的不可恢复测试改为遍历全部分页，保证 507 条关系下仍验证真实停止样本，而不是偶然依赖前 200 条排序。

## 十二、第四轮已落地：报告历史与生成回执

- 人选详情新增“报告与产物”区，匹配报告、嘉驰推荐报告、简历文档和薪资报告按生成时间列出，并显示独立版本号与校验状态。
- 报告条目可直接打开统一产物查看器；候选详情接口只返回公开元数据，不返回正文或内部文件路径。
- 当前页面条发起推荐报告后明确说明已建立生成计划，并提供“打开生成计划”进入对应工作流，不再只显示泛化的“操作已提交”。

## 十三、第五轮已落地：候选动作幂等与结果回读

- 当前页面简历评估会回读 Agent 运行状态直到完成、失败或仍在后台运行；同一快照已有运行时复用原任务并明确提示，不再永远停留在“评估已启动”。
- 候选动作的两个前端入口增加同步提交锁，快速双击只提交一次；后端返回已执行或幂等重放时显示“此前已完成”，而不是误报为本次新写入。
- 候选动作提交冲突后主动回读最新候选状态，避免预检期间状态变化后继续展示旧阶段。
- “评分复核”改为只记录顾问结论事件，不再把已联系、已推荐等后续阶段倒退到 S1；Core 回归测试覆盖推荐阶段复核后的阶段保持。

## 十四、第六轮已落地：Agent 候选人问答证据链

- 主 Agent 对候选人的“哪些方面匹配、为什么匹配、从哪些点判断”等问题，统一读取当前人岗评估结构，不再交给模型自由压缩成一句泛化结论。
- 回答按“直接匹配”“部分匹配或证据不足”“判断边界”“需要核验”“下一步”分组；直接证据、判断说明和证据缺口分别呈现。
- 过滤评估器把整段 JD 拼成一条总门槛的重复项，避免仅凭学历证据显示“整条硬门槛已满足”；真实线上验证覆盖士兰微电源专家候选人 #810。

## 十五、第七轮已落地：工作台口径、分析恢复与模块空态

- 岗位看板与人选模块统一分页拉取完整数据，不再把 API 单页上限当成全部结果；当前正式库 132 个岗位和 507 条人岗关系均按真实总量读取。

## 十六、第八轮已落地：全模块导航、可逆动作与原生交付
